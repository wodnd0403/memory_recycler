# Memory Recycler 제안서 피드백

## 총평

수정 방향은 매우 좋아졌다. 이전 버전보다 `프로젝트 한 줄 소개`, `핵심 게임 루프`, `구현 범위`, `요구사항 명세서`, `기능 명세서`, `데이터 흐름도`가 추가되어 “멋진 세계관”에서 “구현 가능한 텀프로젝트 제안서” 쪽으로 확실히 가까워졌다.

다만 현재 원본은 여전히 세계관과 캐릭터 설명이 앞쪽에 있고, 구현 범위와 명세가 뒤로 밀려 있다. 게임프로그래밍 수업의 제안서는 교수님이 “무엇을 만들고, 어디까지 만들 수 있고, 어떤 기술로 구현할지”를 빠르게 확인할 수 있어야 하므로, 구현 관련 장을 앞쪽으로 올리는 편이 좋다.

## 꼭 고칠 부분

1. `4. 세계관과 줄거리` 다음에 다시 `4. 주요 캐릭터`가 나와 번호가 중복된다.
2. `구현 범위`, `요구사항 명세서`, `기능 명세서`가 너무 뒤에 있다.
3. `DFD`는 들어간 것이 좋지만, 현재는 일반 텍스트라 도식처럼 보이지 않는다.
4. 기능 요구사항이 `FR-07`까지만 있어 엔딩 분기와 진행 UI가 요구사항에 빠져 있다.
5. 역할 분담과 리스크 대응이 없다. 교수님 관점에서는 구현 가능성을 판단하기 어려운 부분이다.

## 내용 보강 제안

### 구현 범위

현재처럼 `필수`와 `선택`으로 나눈 것은 좋다. 다만 `낮/밤 시간대 시스템`은 핵심 시스템이 아니라 분위기 연출에 가깝기 때문에 선택 기능으로 두는 편이 안전하다. 필수 기능은 반드시 `기억 수집 → 복원 퍼즐 → 선택 → 엔딩`에 집중하는 것이 좋다.

### 요구사항 명세서

`FR-08 선택 누적 결과에 따라 엔딩이 달라져야 한다`, `FR-09 진행 상황이 UI로 표시되어야 한다`, `FR-10 시간대 시스템은 조명과 분위기를 변경할 수 있어야 한다`를 추가하는 것이 좋다.

### 기능 명세서

현재 기능 명세는 좋다. 여기에 `MemoryData`의 내부 필드를 한 번 더 보여주면 구현 신뢰도가 올라간다.

예시:

| 필드 | 타입 | 역할 |
| --- | --- | --- |
| id | string | 기억 데이터 고유 ID |
| title | string | 기억 카드 제목 |
| emotionTag | enum/string | 감정 분류 |
| restoredText | string | 복원된 기억 내용 |
| sentencePieces | string[] | 퍼즐 문장 조각 |
| decision | enum | 보존/삭제/재가공 선택 |

### 역할 분담

역할 분담은 꼭 들어가는 편이 좋다.

| 팀원 | 담당 영역 |
| --- | --- |
| 신동준 | 플레이어 이동/카메라, 폐도시 맵 구성, 시간대 시스템, 시연 영상 정리 |
| 차재웅 | 기억 데이터, 기억 카드 UI, 복원 퍼즐, 선택/엔딩 분기 |
| 공동 | 기획 보완, 테스트, 버그 수정, 발표자료 제작 |

### 리스크 및 축소 계획

이 표가 있으면 “범위 관리가 되는 팀”처럼 보인다.

| 위험 요소 | 대응 방안 |
| --- | --- |
| 3D 맵 제작 시간이 오래 걸림 | 중앙 광장과 인접 거리 중심으로 축소 |
| 낮/밤 시스템 구현 지연 | 고정 밤 분위기 또는 단순 조명 전환으로 대체 |
| 엔딩 연출 제작 시간이 부족 | 텍스트 엔딩 UI와 색상 변화로 대체 |
| 기억 데이터 제작 부담 | 6개 계획, 최소 3개 구현 |
| 퍼즐 UI 구현 난이도 | 드래그 대신 클릭 순서 선택 방식으로 단순화 |
