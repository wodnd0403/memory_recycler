# Memory Recycler 3D 7분 최종 발표 계획

## 발표 목표

- 공지된 5~10분 범위 안에서 7분 발표로 구성한다.
- PPT는 12장으로 구성하고, 10번 슬라이드에 2분 30초 시연 영상을 배치한다.
- 실제 구현된 기능만 말한다.
- 핵심 메시지는 다음 한 문장으로 고정한다.

> Memory Recycler 3D는 기록창을 단순 UI가 아니라 기억 렌즈로 사용해, 3D 폐도시의 기억을 화면과 공간의 겹침으로 복원하는 게임이다. 마지막에는 아카이브가 플레이어의 선택과 복원 방식을 다시 심문한다.

## 전체 시간 배분

| 구간 | 슬라이드 | 시간 |
|---|---:|---:|
| 도입 | 1~3 | 55초 |
| 핵심 메커닉 | 4~8 | 2분 35초 |
| 시스템 구조 | 9 | 30초 |
| 시연 영상 | 10 | 2분 30초 |
| 정리 | 11~12 | 30초 |
| 합계 | 12장 | 7분 |

## 슬라이드 구성

| # | 제목 | 핵심 메시지 | 넣을 스크린샷 | 예상 시간 |
|---|---|---|---|---:|
| 1 | Memory Recycler 3D | 폐도시의 기억을 복원하는 3D 탐험 퍼즐 | 타이틀 화면 또는 폐도시 전경 | 15초 |
| 2 | 개발 배경 | 기존 문장 퍼즐을 공간 기반 기억 복원으로 확장했다 | 폐도시 전경 + 기억 구체 | 20초 |
| 3 | 게임 콘셉트 | 플레이어는 도시의 기억을 수거하지만, 아카이브도 플레이어를 기록한다 | 기억 구체 회수 장면 | 20초 |
| 4 | 핵심 아이디어: 기억 렌즈 | Tab 기록창은 메뉴가 아니라 세계를 읽는 렌즈다 | Tab 렌즈 ON/OFF 비교 | 35초 |
| 5 | 게임 진행 흐름 | 수집, 복원, 선택, 아카이브 심문으로 루프가 닫힌다 | 진행 흐름도 | 30초 |
| 6 | 기억 렌즈 퍼즐 3종 | 겹치기, 가리기, 멈추기로 기억을 복원한다 | MR3D_002/003/006 3분할 | 35초 |
| 7 | 보존/삭제/재가공 선택 | 같은 기억도 선택에 따라 증언, 침묵, 재가공 기록이 된다 | 선택 UI | 25초 |
| 8 | PlayerMemoryLog와 아카이브 심문 | 게임은 기억뿐 아니라 플레이어의 행동도 기록한다 | 아카이브 심문 UI | 30초 |
| 9 | 시스템/클래스 구조 | 주요 매니저가 수집, 렌즈, 기록, 엔딩을 분담한다 | 클래스 구조 다이어그램 | 30초 |
| 10 | 시연 영상 | 한 루프로 핵심 재미와 엔딩 반전을 보여준다 | 2분 30초 영상 | 150초 |
| 11 | 한계점 및 개선 방향 | 3개 특수 퍼즐을 8개 기억 전체로 확장할 수 있다 | 개선 방향 표 | 20초 |
| 12 | 마무리 | 마지막으로 재활용된 것은 기억이 아니라 선택이다 | 엔딩 화면 | 10초 |

## 발표 톤

- 기능을 많이 나열하기보다 "렌즈로 세계를 읽는다"는 경험을 반복해서 각인한다.
- 코드 설명은 9번 슬라이드에서만 짧게 다룬다.
- 시연 영상 전에 조작과 목표를 너무 길게 설명하지 않는다.
- 시연 영상 후에는 한계와 개선 방향으로 빠르게 닫는다.

## 반드시 피할 것

- 구현되지 않은 8개 전체 특수 렌즈 퍼즐처럼 말하지 않는다. 현재 특수 퍼즐은 MR3D_002, MR3D_003, MR3D_006 중심이다.
- 플레이어 이동/전투/정밀 물리 같은 핵심이 아닌 내용을 오래 설명하지 않는다.
- 코드 원문을 PPT에 길게 붙이지 않는다.
- 레퍼런스 자료의 문장, 표, 이미지를 그대로 복사하지 않는다.
