## 1. 제안서 핵심 목표

제안서의 게임 목표는 5~10분 안에 다음 경험을 제공하는 3D 프로토타입이다.

- 3인칭 폐도시 탐험
- 기억 구체 회수
- 기억 복원 퍼즐
- 보존 / 삭제 / 재가공 선택
- 선택 누적에 따른 엔딩 분기
- 중앙 아카이브 중심의 원형 도시 구조
- 낮 / 저녁 / 밤 / 새벽 시간대 변화
- 기억 수거원, 중앙 아카이브 관리자, 미아, 이름 없는 시민들의 흔적

현재 개발은 “핵심 루프는 있음”에 가깝다. 다만 발표에서 체감되는 완성도는 아직 안정성, 퍼즐 재미, 엔딩 마무리, 맵 경계, 등장인물 연출에 달려 있다.

| --- | --- | --- |
| 3인칭 이동 | 부분 구현 | 이동, 달리기, 점프, 모델 적용은 있음. 카메라 충돌/근접 시야는 최근 보정했으나 실제 플레이 재검증 필요. |
| 기억 구체 회수 | 구현 | `MemoryObject3D`, `MemoryManager3D`, `UIManager3D` 흐름 존재. |
| 기억 데이터 | 구현 | `MR3D_001`~`MR3D_008` 데이터 자산 존재. 제안서의 최소 6개보다 많음. |
| 복원 퍼즐 | 부분 구현 | 문장 조각 순서 선택 방식 존재. 재미 요소는 약하고 오답/힌트/긴장감은 부족. |

| 개인 엔딩 | 미구현 또는 약함 | 제안서에는 “주인공의 기억 파일 복원 + 보존” 개인 엔딩이 있음. 현재는 다수결 3엔딩 중심. |
| 시간대 시스템 | 부분 구현 | `WorldToneController3D`가 조명, 안개, 별/달, 시간 HUD를 다룸. 실제 체감은 플레이 확인 필요. |
| 맵 구조 | 부분 구현 | 중앙 아카이브, 원형 도로, 주거/학교/행정/외곽 컨셉은 있음. 배치/충돌/탈출 방지가 계속 조정 중. |
| 등장인물 | 약함 | 기억 수거원은 있음. 미아/시민/아카이브 관리자는 직접 캐릭터보다는 기록/오브젝트로 암시됨. |
| 저장/이어하기 | 구현 | `MemoryManager3D` 저장 구조 존재. ID 누락 방어 경고도 있음. |
| 발표 안정성 | 진행 중 | `PlayBoundary3D`, 엔딩 버튼, 퍼즐 재진입 보강이 Claude 쪽 변경으로 들어온 상태. 별도 QA 필요. |

## 3. 가장 큰 현재 문제

### A. 게임 자체의 재미가 약함

현재 재미의 핵심은 “기억을 찾아서 문장을 맞추고 선택한다”인데, 퍼즐이 단순 클릭 순서 맞추기라 긴장감과 판단의 여지가 약하다.

하지만 발표 직전에는 퍼즐 UI를 크게 갈아엎는 것보다 작은 규칙을 얹는 편이 안전하다.

추천 보강:

- 오답 횟수 카운트
- 3회 오답 시 첫 조각 힌트 또는 자동 배치
- 기억마다 가짜 조각 1개 추가 가능
- 오답 시 기억 노이즈 / 토스트 / 짧은 화면 연출
- 복원 성공 후 “이 기억을 어떻게 처리할지”의 의미를 더 강하게 표시

### B. 퍼즐 중 UI를 닫았을 때의 흐름

기억 구체는 회수 후 사라지므로, 퍼즐을 닫았을 때 다시 복원을 시작할 경로가 명확해야 한다.

Claude 변경으로 `OpenNextPendingMemoryCard()`가 추가된 상태로 보인다. 실제로 다음 흐름이 되는지 검증해야 한다.

- 기억 회수
- 복원 퍼즐 열기
- 닫기
- Tab 아카이브 또는 기억 카드에서 다시 복원 가능
- 진행이 막히지 않음

### C. 엔딩 후 마무리 부족

엔딩 UI만 뜨고 게임이 계속 이어지면 발표에서 “끝난 느낌”이 약하다.

현재 Claude 변경으로 엔딩 패널에 `타이틀로`, `새 게임`, `종료` 버튼이 들어온 것으로 보인다. 실제 검증할 것:

- 엔딩 중 플레이어 입력 차단
- 타이틀로 돌아가기 가능
- 새 게임 시 저장 삭제 및 초기 위치 복귀
- 빌드에서는 종료 버튼이 `Application.Quit()` 실행
- 에디터에서는 종료 안내만 표시

### D. 등장인물 체감 부족

제안서 주요 캐릭터:

- 기억 수거원
- 중앙 아카이브 관리자
- 미아
- 이름 없는 시민들

현재는 대부분 기억 데이터/터미널/오브젝트로만 존재한다. 남은 시간이 적다면 완전한 NPC보다 “기억 잔상” 방식이 현실적이다.

추천:

- 미아: 파란 우산 근처에 반투명 실루엣 또는 음성 기록 터미널
- 중앙 관리자: 아카이브 접근 시 안내/경고 대사 UI
- 시민들: 주거/학교/행정 구역에 짧은 잔상 텍스트 또는 실루엣

### E. 맵 탈출 및 충돌 불일치

현재 가장 플레이 감각을 망치는 문제다.

좋은 게임들은 보통 다음 방식으로 처리한다.

- 보이는 모델과 충돌 모델을 분리한다.
- 장식물에는 콜라이더를 붙이지 않는다.
- 플레이어가 막혀야 하는 곳은 단순한 프록시 콜라이더로만 막는다.
- 플레이 영역 바깥은 보이지 않는 경계 + 보이는 폐허 벽으로 함께 막는다.
- 플레이어가 그래도 나가면 안전 위치로 되돌리는 failsafe를 둔다.

Claude 변경으로 `PlayBoundary3D`와 `MR3D_Bootstrap`이 추가된 상태다. 다만 기본 반경이 넓어 실제 맵 탈출을 막는지 확인 필요.

## 4. 다음 개발 우선순위

### P0: 발표 안정화

1. 맵 탈출 방지 실제 검증
2. 허공에서 막히는 지점 / 보여도 통과되는 지점 QA
3. 퍼즐 닫기 후 재진입 검증
4. 엔딩 후 타이틀/새 게임/종료 흐름 검증
5. 새 게임/이어하기 저장 상태 검증
6. 3개 처리 후 아카이브 엔딩 진입 검증

P0는 새 기능보다 “막히지 않음”이 목표다.

### P1: 재미와 제안서 체감 보강

1. 퍼즐 오답/힌트/가짜 조각 최소 보강
2. 미아/시민/아카이브 관리자 잔상 연출
3. 개인 엔딩 조건 추가 여부 결정
4. 시간대 변화 체감 강화

P1은 발표에서 “기획서와 연결되어 보이는가”를 담당한다.

### P2: 후순위 확장

1. 퍼즐 UI 전면 개편
2. NPC 이동/대화 시스템
3. 컷신 카메라 시퀀스 고도화
4. 엔딩별 전용 연출/씬 전환

P2는 지금 넣으면 리스크가 크다.

## 5. Claude Code에게 맡길 작업

현재 Claude가 P0 작업을 이미 일부 수행한 것으로 보인다. 추가로 시킬 때는 “수정”보다 “검증 및 최소 보정” 중심이 좋다.

```text
Unity 프로젝트 Memory Recycler의 발표 안정화 작업을 검증하고 최소 보정해줘.

조건:
- Build Prototype Scene (Destructive) 실행 금지
- 기존 씬 연결 유지
- 큰 리팩터링 금지
- 최근 추가된 PlayBoundary3D, MR3D_Bootstrap, UIManager3D 엔딩/퍼즐 변경을 되돌리지 말 것

검증/작업:
1. 맵 경계가 실제 플레이 영역 탈출을 막는지 확인하고, 너무 넓으면 발표 맵 크기에 맞게 반경/안전 위치 조정.
2. 퍼즐 UI를 닫은 뒤에도 해당 기억을 다시 복원할 수 있는지 확인.
3. 엔딩 UI에서 타이틀로 / 새 게임 / 종료 버튼이 정상 작동하는지 확인.
4. 새 게임 후 기억 구체, 저장 데이터, 플레이어 위치가 초기화되는지 확인.
5. 허공에서 막히는 장식 콜라이더가 남아 있으면 장식물 콜라이더만 제거.

수정 후:
- 변경 파일 목록
- 재현 절차
- Unity Console 에러 여부
- 발표 5분 루프 확인 결과를 적어줘.
```

## 6. Codex가 맡을 작업

Claude가 코드 안정화를 진행하는 동안 Codex는 다음을 맡는 것이 안전하다.

- 제안서 대비 구현 현황 문서 유지
- QA 체크리스트 업데이트
- Claude 결과 코드 리뷰
- 퍼즐 재미 보강 기획안 작성
- 다음 프롬프트 작성

같은 파일을 동시에 만지는 것은 피한다. 특히 `UIManager3D.cs`, `MemoryManager3D.cs`, `Prototype3D.unity`, `MR_ProposalMapCompositionPass.cs`는 충돌 위험이 크다.

## 7. 발표 QA 체크리스트

### 시작 / 저장

- [ ] 새 게임 버튼이 저장 삭제 여부를 명확히 안내한다.
- [ ] 이어하기는 저장이 있을 때만 가능하다.
- [ ] 새 게임 후 플레이어가 시작 위치에 있다.
- [ ] 새 게임 후 기억 구체가 다시 나타난다.

### 기본 조작

- [ ] WASD 이동 가능.
- [ ] Shift 달리기 가능.
- [ ] 점프 가능.
- [ ] 카메라가 장애물 근처에서 1인칭처럼 빨려 들어가지 않는다.
- [ ] 카메라가 점프 중 심하게 튀지 않는다.

### 맵 / 충돌

- [ ] 플레이 영역 밖으로 나갈 수 없다.
- [ ] 경계 밖으로 나가면 안전 위치로 복귀한다.
- [ ] 허공에서 막히는 지점이 없다.
- [ ] 통과하면 안 되는 큰 구조물은 통과되지 않는다.
- [ ] 장식용 전선/얇은 파이프/데칼은 플레이를 방해하지 않는다.

### 기억 루프

- [ ] 기억 구체 접근 시 상호작용 안내가 뜬다.
- [ ] E 입력으로 기억 카드가 열린다.
- [ ] 기억 카드에서 복원 퍼즐로 진입한다.
- [ ] 퍼즐을 닫아도 다시 복원할 수 있다.
- [ ] 퍼즐 성공 후 기억 에코가 뜬다.
- [ ] 복원 후 보존/삭제/재가공 선택이 가능하다.
- [ ] HUD의 회수/복원/처리 수치가 갱신된다.

### 엔딩

- [ ] 처리 0~2개 상태에서 아카이브 접근 시 잠금 안내가 뜬다.
- [ ] 처리 3개 이상이면 엔딩 UI가 뜬다.
- [ ] 보존이 가장 많으면 복원 엔딩.
- [ ] 삭제가 가장 많으면 정적 엔딩.
- [ ] 재가공이 가장 많으면 편집 엔딩.
- [ ] 엔딩 중 플레이어 조작이 차단된다.
- [ ] 타이틀로 버튼이 시작 메뉴로 돌아간다.
- [ ] 새 게임 버튼이 상태를 초기화한다.
- [ ] 종료 버튼이 빌드/에디터에서 의도대로 동작한다.

### 제안서 체감

- [ ] 중앙 아카이브가 맵 중심으로 보인다.
- [ ] 주거/학교/행정/외곽 구역 구분이 가능하다.
- [ ] 미아의 파란 우산 또는 흔적이 확인된다.
- [ ] 시민 기억들이 단순 아이템이 아니라 사건 조각처럼 느껴진다.
- [ ] 시간대 변화가 HUD뿐 아니라 조명/분위기로 느껴진다.

## 8. 퍼즐 재미 보강안

현재 구조를 크게 바꾸지 않고 다음 단계로 개선하는 것을 권장한다.

### 1단계: 오답과 힌트

- `wrongAttemptCount` 추가
- 오답 1회: “문장 흐름이 어긋났습니다”
- 오답 2회: 첫 조각 힌트 표시
- 오답 3회: 첫 조각 자동 선택 또는 정답 첫 단어 강조

장점: 구현이 작고 발표 중 효과가 바로 보인다.

### 2단계: 가짜 조각

`MemoryData3D`에 선택 필드로 `decoyPieces`를 추가한다.

- 기존 데이터가 없어도 동작
- 일부 기억만 가짜 조각 사용 가능
- UI는 기존 버튼 생성 로직을 유지

주의: 저장 구조를 건드리지 않는 선에서 해야 한다.

### 3단계: 선택의 의미 강화

퍼즐 성공 후 선택 버튼 위에 짧은 설명을 붙인다.

- 보존: 진실을 남긴다
- 삭제: 고통과 증거를 지운다
- 재가공: 안정된 이야기로 편집한다

이것만으로도 제안서의 윤리적 선택 체감이 강해진다.

## 9. 다음 결정 필요

1. 개인 엔딩을 발표에 넣을지 여부
   - 넣는다면 `MR3D_006` 수거원의 빈 파일을 복원하고 보존했을 때 우선 발동하는 방식이 가장 간단하다.

2. 등장인물 구현 범위
   - 완전한 NPC 대신 기억 잔상/텍스트/음성 기록으로 처리하는 것을 추천한다.

3. 퍼즐 개선 범위
   - 발표 전에는 오답/힌트까지만 권장.
   - 가짜 조각은 시간이 남으면 추가.

4. 맵 경계 방식
   - 보이지 않는 원형 경계만 둘지, 폐허 장벽을 시각적으로 추가할지 결정 필요.
