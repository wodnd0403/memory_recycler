# Memory Recycler 3D 최종보고서/PPT 레퍼런스 분석

> `Docs/temp`의 이전 차시 최종보고서/발표자료 46개를 분석해, Memory Recycler 3D
> 최종보고서와 발표 PPT 제작에 참고할 "구성 방식과 패턴"을 선별하는 문서.
> 배치가 끝날 때마다 누적 갱신된다. 진행 상태는 `REFERENCE_REVIEW_PROGRESS.md` 참조.

## 표절 방지 원칙

- 레퍼런스에서 가져오는 것은 **구성 방식(목차 흐름, 슬라이드 배분, 시연 구성)과 좋은 패턴**뿐이다.
- **문장, 이미지, 코드, 표를 그대로 복사하지 않는다.** 요약/메모도 원문 인용이 아니라 구조 설명으로만 남긴다.

### 참고 가능한 요소
- 목차/섹션 순서와 비중 (예: 개요 → 기획 → 구현 → 시연 → 회고)
- 슬라이드 수 배분, 한 슬라이드당 정보 밀도
- 스크린샷/영상 배치 방식, 캡션 스타일
- 시스템 설명 다이어그램의 추상화 수준
- 트러블슈팅/회고 섹션을 다루는 방식
- 데모 흐름(플레이 순서) 소개 방식

### 참고하면 안 되는 요소
- 문장 표현 그대로 복사 (한 문장이라도 금지)
- 타 팀 게임의 스크린샷/아트/로고
- 코드 블록, 표 데이터의 그대로 이식
- 타 팀 고유의 기획 콘텐츠(스토리/캐릭터 설정)를 변형 없이 차용

## 배치별 분석 기록

### 배치 1 (1~8.pptx, 8개) — 완료

- 분석 성공 8 / 실패 0
- 대부분 OpenGL/GLUT 시절 텀프로젝트 발표자료. 공통 골격: 개요(주제/선정이유) → 구현 설명 → 시연 → 후기.
- 핵심 발견: **7.pptx의 "제안서 vs 최종 결과물" 비교 프레임**. 모든 슬라이드를
  "기존 구현 방향 / 최종 구현 방향" 두 칼럼으로 놓고 마지막에 체크리스트(V) 요약으로 닫는다.
  제안서가 이미 있는 Memory Recycler 3D 최종보고서에 그대로 응용 가능한 구조.
- 반면교사: 1.pptx(소스분석 슬라이드 7장 연속), 3.pptx(함수 시그니처 나열) —
  코드 원문을 그대로 슬라이드에 붓는 방식은 전달력이 죽는다. 코드는 "설계 의도 한 줄 + 최소 발췌"로.
- 다음 배치 시작: 9.pptx / 남은 파일: 38

### 배치 2 (9~16.pptx, 8개) — 완료

- 분석 성공 8 / 실패 0
- **9.pptx가 유일한 Unity/C# 레퍼런스** (현재까지): 구현 범위 → 컴포넌트 단위(C# 스크립트별) 코드 설명.
  Memory Recycler 3D도 Unity이므로 시스템 설명 구획(매니저/플레이어/오브젝트/카메라) 방식 참고 가치.
- 패턴 수확:
  - 14.pptx: 개발목표에 **O/X 달성 표기** + "미구현 → 대체 구현" 명시 (7.pptx 체크리스트의 컴팩트판)
  - 12.pptx: 제안서 원문을 앞에 재제시하고 항목별 개발 범위로 매핑, 마지막에 주차별 일정표
  - 11.pptx: 벤치마킹(원작에서 가져온 감각) 섹션
  - 14.pptx: 시연 직전 "조작법" 슬라이드 — 라이브 데모 안전장치
- 반면교사: 13.pptx처럼 엔진 일반론(유니티 장단점)에 슬라이드를 쓰면 게임 설명이 밀린다.
- 다음 배치 시작: 17.pptx / 남은 파일: 30

### 배치 3 (17~25, 9개) — 완료

- 분석 성공 7 / 파싱 실패 2 (19.hwp, 21.hwp — OLE 바이너리, 도구로 추출 불가. 수동 열람 필요)
- 핵심 발견:
  - **17.pptx: "거울로만 보이는 귀신" 메커닉** — Memory Recycler 3D의 "렌즈로만 보이는 기억 잔상"과
    컨셉 구조가 같다. "육안으로는 안 보이고 특정 장치로만 보인다"는 메커닉을 짧고 명확하게
    설명하는 화법(상황 설정 → 장치의 역할 → 플레이어 행동)이 그대로 참고된다.
  - **25.pptx ↔ 7.pptx 페어**: 같은 저자의 제안서(25)와 최종보고(7). 제안서의 "구현 방향" 슬라이드가
    최종보고에서 "기존 vs 최종" 비교 슬라이드로 1:1 변환된다 — 제안서가 있는 우리 프로젝트가 따라할
    가장 구체적인 모델.
  - 22.pptx: 연출 시퀀스를 단계 분해(들기→가져오기→장착→완료)로 설명 — 아카이브 리빌/렌즈 복원
    연출 설명에 응용 가능.
  - 24.pptx(Unity): 스크립트 파일 단위 설명 + "향후 개발 방향" 마무리 섹션.
- 다음 배치 시작: 26.docx / 남은 파일: 21
